# 博客文章是否要做多语言？分析摘要

## 当前状态

- **界面**：博客列表/详情页的按钮、标题、标签等已支持中/英/日/韩（与全站 i18n 一致）。
- **内容**：30 篇文章的标题、摘要、正文目前均为**中文**，未按语言拆分。

## 做多语言的好处

| 维度 | 说明 |
|------|------|
| **受众** | 英文/日文/韩文用户可直接阅读，扩大潜在用户与留存。 |
| **SEO** | 各语言独立 URL（如 `/en/blog/xxx`）+ 正确 hreflang，有利于多地区搜索收录。 |
| **品牌** | 与全站多语言体验一致，显得更完整、更国际化。 |

## 不做或延后的理由

| 维度 | 说明 |
|------|------|
| **成本** | 30 篇 × 4 语言 = 120 套内容；人工翻译或审校工作量大，机翻需校对质量与语气。 |
| **主受众** | 若主要用户是中文用户，多语言博客的阅读量可能集中在中文，ROI 不高。 |
| **维护** | 每次更新文章都要同步多语言版本，容易遗漏或不同步。 |
| **重复内容** | 同一主题多语言需做好 hreflang / canonical，否则可能被搜索引擎视为重复。 |

## 建议结论

- **主站以中文用户为主、资源有限**  
  → **暂不**为博客正文做多语言；保持**界面多语言 + 正文中文**即可。等有明确海外流量或需求再上多语言内容。

- **希望拓展海外或做多地区 SEO**  
  → **分阶段**：  
  1. 先为「热门/精选」几篇（如 3–5 篇）提供英文版，并做好 `/en/blog/xxx` 与 hreflang。  
  2. 数据结构上预留「按语言存标题/摘要/正文」，当前只填中文，后续再补其他语言。

- **折中做法**  
  → 在文章数据中增加 `locale` 或按语言分字段（如 `titleEn`、`bodyEn`），先只维护中文；等有翻译资源时再填英文等，列表/详情页按当前站点语言优先展示对应语言版本，无则回退中文。

## 技术实现要点（若将来做）

- 文章数据：`Article` 按语言扩展（如 `title: Record<Locale, string>`）或按语言拆文件（`articles.zh-CN.ts` / `articles.en.ts`）。
- 路由：保持 `/blog/[slug]`，通过当前站点 locale 取对应语言内容；或为英文单独路径如 `/en/blog/[slug]` 与 sitemap/hreflang 一致。
- SEO：在 `<head>` 中为同一 slug 各语言 URL 输出 `hreflang`，并指定默认语言与 canonical。
